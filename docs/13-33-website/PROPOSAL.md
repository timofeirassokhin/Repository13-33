# 13-33.pro — Предложение по архитектуре, стеку, дизайну и рабочей схеме

**Версия 1.0 · май 2026**
**Демо-стенд:** [preview.13-33.pro](https://preview.13-33.pro/)

---

## Резюме на одной странице

Что строим: **контентно-коммерческий хаб** для зонтичного бренда «Пространство 13-33». Один сайт несёт два пространства — *Духовно-психологическое* (`13-33.pro/`) и *Экспертное* (`13-33.pro/expert`). Общая инфраструктура, общие эксперты, переключатель в шапке, слегка различная стилистика и фильтры.

**Главная функция:** служить базой смыслов и точкой входа в продукты. Посетитель приходит «с запросом» (тревога / отношения / поиск себя), находит свой материал, попадает на нужный продукт, идёт в кассу через GetCourse. Параллельно — журнал, методы, эксперты, события на Арбате.

**Архитектурный фундамент — три cross-cutting таксономии:** `Темы` × `Запросы` × `Методы`. Каждый объект сайта (статья, продукт, эксперт, событие, квиз) тегируется по этим осям. Из любой точки сайта пользователь может перейти в любую другую через совпадение тегов. Это превращает сайт из дерева в **граф** — что и было целью.

**Стек:** Payload CMS 3 + Next.js 15 + Postgres + pgvector + Cloudflare. Self-hosted на том же VPS, где живут CRM/MemPalace/uploader. TypeScript end-to-end. Schema-as-code, AI-friendly.

**Связка с существующей инфрой:** Twenty CRM остаётся **редакционным workflow** (Idea → Draft → Publication), Payload — **публикационным CMS**, n8n — мост между ними. MemPalace подключается на V2 как семантический индекс над публикациями и библиотекой.

**Бренд:** уже зафиксирован в логобуке (палитра 7 цветов на Pantone, типографика DIN 2014 + Myriad Pro, иконки, паттерны). Параллельно с сайтом разрабатывается skill `brand-13-33`, который позволит любому агенту в будущем создавать материалы в этом стиле без ре-объяснения.

**Запуск:** 4 фазы, ~10 недель до V1 публичного запуска. Начинаем со скелета и заглушек, чтобы проверить логику и юзабилити; контент наполняется параллельно.

## 1. Цели и аудитория

### 1.1 Цель сайта

Хаб + воронка. Одновременно три функции:

| Функция | Что делает посетитель | Главный KPI |
|---|---|---|
| **Контент-хаб** | Читает большие статьи и блог, подписывается на рассылку | Время на сайте, дочитывания, подписки |
| **Энциклопедия методов** | Изучает подходы (психотерапевтические, телесные, энергетические, традиционные) | Глубина просмотра, переходы на эксперта/продукт |
| **Воронка в продукты** | Узнаёт о курсах/группах/сессиях/событиях, идёт в GetCourse записываться | Заявки на GetCourse, прохождения квиза |

Все три функции должны работать **одновременно**, не конфликтуя. Главный приём — единая трёхосевая таксономия, которая связывает контент с продуктами и экспертами.

### 1.2 Точки входа (откуда приходит посетитель)

- Telegram-канал «13-33» → главная или конкретная статья / событие
- Поиск (Яндекс/Google) → длинная статья по теме, потом — обзор
- Сарафанное → главная или страница метода / эксперта
- QR-код в Пространстве на Арбате → афиша событий
- Реклама / партнёры → лендинг конкретного продукта

### 1.3 Аудитория

Не «эзотерики с горящими глазами», а **взрослые люди в поиске**. Светская, образованная, скорее городская публика, которая хочет интегрировать «внутреннюю работу» (психотерапия, телесные практики, духовный опыт) в свою жизнь — без догм, без шаманизма ради шоу, без чакр в виде иконок.

Тон сайта должен попадать в эту публику: серьёзный, грамотный, без завываний.

### 2.2 Типографика

- **DIN 2014** — основной шрифт (заголовки, текст, UI). Все веса.
- **Myriad Pro** — пара (вторичный): для больших дисплейных вставок, акцентов, длинного тела
- **Цифры в логотипе** — Old-style classical serif (на изображении логобука — Bodoni-подобный)

В прототипе сейчас Bebas Neue (как ближайший free-замен DIN-капса) + Manrope (DIN mixed-case fallback) + Source Sans 3 (Myriad fallback) + Bodoni Moda (цифры лого). Замены работают визуально, но **финальная версия требует лицензированных DIN 2014 и Myriad Pro в `.woff2`**.

### 2.3 Логотип

Знак: круг с дробью **13/33**, цифры классическим засечным шрифтом (Old-style serif).

Дескриптор: «**ДУХОВНО-ПСИХОЛОГИЧЕСКОЕ ПРОСТРАНСТВО**» — мелкая «ДУХОВНО-ПСИХОЛОГИЧЕСКОЕ» сверху + крупная «ПРОСТРАНСТВО» под ней (DIN 2014 Bold, всё капсом).

Для Экспертного Пространства — тот же знак + дескриптор «**ЭКСПЕРТНОЕ ПРОСТРАНСТВО**».

**Lockup-варианты** (зафиксировано в логобуке):
- Vertical: знак сверху, текст под ним (для квадратных позиций — favicon, аватар, OG-image)
- Horizontal: знак слева, двухстрочный текст справа (для шапки сайта, email-подписи)
- Mark-only: только круг с цифрами (для favicon, badge, watermark)

**Цветовые правила фонов**: на тёмных цветах (основной/синий/кирпичный) — белая версия знака; на светлых (голубой/коралловый/оливковый/ваниль) — тёмная.

**Защитное поле** = ширина одной цифры «13» вокруг знака.

### 2.4 Декоративные элементы

- **Паттерн Уильяма Морриса** (растительный/лиственный орнамент) — для фоновых текстур больших баннеров и hero-секций. Использовать дозированно.
- **Мандала** — альтернативный паттерн фоновой текстуры.
- **Иконки-пиктограммы** — 17 штук в линейном стиле с подписями капсом DIN 2014. Используются для функциональных блоков (профиль, обучение, поддержка, покупки, ЦРМ, сайт, уведомление, мобильная версия и т.д.).

### 2.5 «13» и «33»

Самые мистические числа человеческой истории. Главная тема Пространства — **интеграция психологии и духовных практик**. Отсюда: лёгкий налёт мистики в визуале (классические засечные цифры в круге), но интеллигентный современный тон в текстах. Без эзотерических штампов.

## 3. Архитектура контента

### 3.1 Зонтичная структура двух Пространств

```
13-33.pro/                 ← Духовно-психологическое (default)
13-33.pro/expert           ← Экспертное (онлайн-бизнес для экспертов)
```

Поддомен ради чистоты vs подпапка ради SEO-веса — выбираем **подпапку**. Один сайт, общая инфра, общие эксперты, общий движок. Различаются: главная, акценты палитры, наполнение, фильтры рубрикаторов.

В шапке справа — **переключатель** «Духовное ↔ Экспертное».

### 3.2 Тройная таксономия (cross-cutting)

Это центральная идея архитектуры. Три оси пронизывают **все** объекты сайта:

| Ось | Что описывает | Примеры |
|---|---|---|
| **Темы** | Предметную область | психология, телесность, энергии, традиции, философия, отношения, женское/мужское, дыхание, голос |
| **Запросы** | С чем приходит клиент | здоровье, карьера, отношения, поиск себя, тревога, кризис, родительство, деньги |
| **Методы** | Как мы работаем | КПТ, гештальт, телесная терапия, шаманские практики, дыхательные практики, мировые традиции |

Любой объект (статья / продукт / эксперт / событие / квиз) тегируется минимум одной осью, обычно несколькими. Это базис всего графа.

### 3.3 Разделы сайта

```
├── Главная (1 на каждое Пространство)
├── О нас — миссия, философия, история, команда
│
├── Журнал
│   ├── Большие статьи (longread / «канон»)
│   ├── Блог (короткое/среднее, частично из соцсетей)
│   └── Фильтры: темы / запросы / методы / автор / формат
│
├── Темы          ← вход для тех, кто ищет «про что»
├── Запросы       ← вход для тех, кто ищет «с чем пришёл»
├── Методы        ← энциклопедия подходов
├── Эксперты      ← авторы статей и/или авторы продуктов
│
├── Магазин       ← каталог с фильтрами по 3 осям + цена + формат
│   └── Лендинг продукта → hero + ... + кросс-продажи + покупка через GetCourse
│
├── Пространство на Арбате
│   ├── Афиша событий + календарь + запись
│   ├── Репортажи (живая лента, формат блога)
│   └── Галерея пространства
│
├── Квизы и тесты
│   └── Результат → персональный трек: статьи + продукты + эксперт + диагностика
│
└── Сервисное
    ├── Личный кабинет (V2/V3, пока заглушка → GetCourse)
    ├── Поиск (V1: full-text; V2: семантический через pgvector + MemPalace)
    ├── Подписка (V1: GetCourse, V2: возможно собственный ESP)
    └── Юр.: политика, оферта, дисклеймеры
```

### 3.4 Главное меню

Лаконичное, по семантическим точкам входа:

```
ЛОГО   |   Темы  Запросы  Журнал  Магазин  Арбат  Тест-навигатор  О нас   |   🔍 👤 [Духовное ▾]
```

**Эксперты** и **Методы** — внутренние сети графа, не выносятся в основное меню. На них попадают из карточек продуктов, со страниц тем/запросов, из «О нас → Команда».

### 3.5 Сквозные элементы (на каждой странице)

- **Sidebar-баннер квиза** (на статьях, темах, запросах, методах) — призыв пройти тест-навигатор за 3 минуты
- **Карусель «созвучных продуктов»** в подвале — алгоритм по совпадению тегов
- **Слайдшоу афиш** на главной и в footer — события Арбата + новые продукты
- **Лента «новое»** — статья + продукт + событие в одном потоке
- **Блок «связанные»** на каждой странице — рассчитывается на сервере по совпадению тегов

### 3.6 Граф связей — как работает

Каждый объект имеет multi-relations через таксономии. Для текущей страницы X с тегами T(X) считаем для каждого кандидата Y:

```
score(Y) = |T(X) ∩ T(Y)| × вес_по_оси × свежесть_бонус
```

Кандидаты ограничиваем по типу (на странице темы → ищем продукты + статьи + эксперты + события). Кеш на 1 час, инвалидация при публикации.

С первого дня собираем телеметрию (Plausible custom events): клики по карточкам, открытия квиза, переходы на GetCourse. Дашборд в Payload-админке: топ-пары тегов, мёртвые теги, объекты-сироты без связей.

## 4. Шаблоны страниц

Здесь описана логика каждого типа. Полный wireframe-каталог — в `docs/13-33-website/01-architecture.md`, секция 6.

### 4.1 Главная (Духовное)

10 блоков сверху вниз:

1. **Hero** — фоновое слайдшоу из фото мероприятий и лиц основателей + слоган «Пространство, в котором случается ВСЁ / и ВСЁ случается». Минимум текста, максимум атмосферы.
2. **Лента «новое»** — карусель из 5-8 свежих карточек (статьи + продукты + события вперемешку)
3. **Три двери** — три точки входа в каталог: «По теме», «По запросу», «По методу»
4. **Карусель главных продуктов** — 6 featured из магазина
5. **Афиша Арбата (compact)** — 3 ближайших события + ссылка на полную афишу
6. **Эксперты (compact)** — 6-8 миникарточек ведущих
7. **Канон** — 3-4 ключевых лонгрида (поле featured)
8. **Широкий баннер тест-навигатора**
9. **О Пространстве (тизер)** — короткий манифест + ссылка на «О нас» + переключатель на Экспертное Пространство
10. **Подписка** (через GetCourse) + Footer

### 4.2 Карточка статьи

Hero (тип, теги, заголовок, лид, автор, время чтения, cover) → тело (Lexical) → сайдбар (оглавление + баннер квиза + миникарточка автора) → CTA «хочу глубже» с подбором продуктов автора по тегам статьи → связанные статьи → карусель созвучных продуктов.

### 4.3 Лендинг продукта

Hero (афиша, тип, эксперт, цена, кнопка GetCourse) → «что вас ждёт» → описание → программа → метод(ы) → расширенная карточка эксперта → отзывы (V2) → FAQ → кросс-продажи (по совпадающим тегам) → связанные статьи → CTA-блок.

### 4.4 Страница эксперта

Hero (фото, имя, роль, короткое bio, кнопка «записаться») → расширенное bio → методы которыми работает → продукты которые ведёт → последние статьи → контакты (Telegram, расписание, кабинет на Арбате).

### 4.5 Страницы темы / запроса / метода

Один шаблон, акцент меняется. Hero таксономии (название + 1-2 абзаца определения) → CTA на квиз-навигатор → связанные продукты → связанные статьи → методы для этого запроса (только для запроса) → эксперты, работающие с этим (для запроса/метода) → связанные события Арбата.

### 4.6 Магазин — каталог

Sticky-сайдбар фильтров (тип, темы, запросы, методы, эксперт, цена, формат) → активные фильтры в виде чипов → сетка карточек продуктов с сортировкой → пагинация.

### 4.7 Афиша Арбата

Hero (фото пространства + адрес) → переключатель «Календарь | Список» → события (попап с инфо + «Записаться») → лента прошедших событий с репортажами.

### 4.8 Квиз и результат

Минимальный header без отвлекающих ссылок → прогресс-бар → вопросы (radio/checkbox/шкала) → на последнем вопросе CTA «Получить рекомендации» → переход на `/quiz/[slug]/result?token=...` с персональным треком (3-5 продуктов + 3-5 статей + 2-3 эксперта + кнопка «записаться на личную диагностику»).

## 5. Дизайн-система

### 5.1 Стилистический манифест

- **Тёмная сложная палитра** + ванильные карточки контента + коралловый CTA — основной режим
- **Sans-serif капсом** для заголовков (DIN 2014 / Bebas Neue) — характер плакатный, серьёзный
- **Старо-стильный сериф** только для цифр в логотипе и редких декоративных вставок («13», «33», «01», «02»)
- **Высокий контраст**: тёмный фон vs ванильные карточки vs коралловые CTA
- **Плашки скруглённые** (24-32px) — стиль наследуется из GetCourse-макетов брендбука
- **Кнопки pill** (полностью круглые края)
- **Декоративные числа полупрозрачно** на фоне секций («01», «02» в Doors блоке)
- **Воздух щедрый**: 96-128px между секциями, плакатные размеры в hero

### 5.2 Дизайн-токены

```css
/* Палитра — фиксированная */
--c-primary:  #1E252D;  --c-vanilla: #EAD0A6;  --c-coral:  #EB8260;
--c-blue:     #2B495B;  --c-teal:    #7C9C90;  --c-brick:  #8B3F28;
--c-olive:    #8E843D;

/* Производные слои */
--bg-base, --bg-elevated-1, --bg-elevated-2, --bg-vanilla, --bg-vanilla-soft
--text-on-dark, --text-on-dark-soft, --text-on-dark-muted
--text-on-vanilla, --text-on-vanilla-soft, --text-on-coral
--border-subtle, --border-vanilla

/* Скругления */
--r-sm: 8px;   --r-md: 16px;  --r-lg: 24px;  --r-xl: 32px;  --r-pill: 999px;

/* Ритм */
--s-1..--s-8: 8px → 128px (степенной шаг)

/* Шрифты — порядок: лицензированный → fallback */
--font-display:     'DIN 2014', 'Bebas Neue', 'Manrope', sans-serif;
--font-display-alt: 'DIN 2014', 'Bebas Neue', 'Manrope', sans-serif;
--font-ui:          'DIN 2014', 'Manrope', sans-serif;
--font-body:        'Myriad Pro', 'Source Sans 3', sans-serif;
--font-logo-numbers:'Bodoni Moda', serif;
```

Экспертное Пространство переопределяет токены через `[data-space="expert"]`. Ядро компонентов — общее.

### 5.3 Минимальный набор компонентов

- **Logo** — mark, mark+text horizontal, mark+text vertical (light/dark, 3 размера)
- **Button** — primary coral / secondary blue / ghost
- **Tag chip** — 7 цветовых вариантов (по палитре)
- **Card** — vanilla light / dark
- **Header pill** — sticky, с навигацией и иконками
- **Space switcher** — Духовное / Экспертное
- **Door card** — точка входа в каталог с гигантской цифрой
- **Carousel** — горизонтальный скролл
- **Quiz banner** — wide / sidebar

## 6. Технологический стек

### 6.1 Финальный выбор

```
Frontend:    Next.js 15 (App Router, RSC, ISR)
CMS:         Payload CMS 3 (TypeScript schema-as-code, Lexical editor)
БД:          Postgres 16 + pgvector (граф связей + векторный поиск V2)
Хранение:    MinIO (S3-совместимое, self-hosted)
Стили:       Tailwind CSS + CSS variables (дизайн-токены)
UI-кит:      shadcn/ui (копия в репо, можно править под бренд)
Анимации:    Framer Motion (дозированно)
Аналитика:   Plausible (self-hosted, GDPR-ок, без cookie-баннеров)
Поиск:       V1 — Postgres FTS;  V2 — pgvector + связь с MemPalace
Auth:        Payload Auth (V2 для ЛК; V1 — вход через GetCourse)
CDN/WAF:     Cloudflare
CI/CD:       GitHub Actions → Docker → VPS
Мониторинг:  Sentry (ошибки) + Plausible (продукт)
```

Хостинг — тот же VPS `186.246.1.61`, где живёт остальной стек (Twenty, MemPalace, Bot, n8n, Traefik). Это даёт нативные внутренние сети и общие тома, без сетевых задержек на бэкенде.

### 6.2 Почему Payload — четыре ключевых причины

1. **Граф связей нативно**. Связи многие-ко-многим (статья ↔ метод ↔ тема ↔ запрос ↔ продукт ↔ эксперт ↔ событие) описываются в TypeScript-схеме одной декларацией. Не «прибиты гвоздями» как в традиционных CMS.
2. **Production-grade админка из коробки**: Lexical rich-text-editor (как у Notion), медиатека, версии, draft/publish, ролевая модель, локализация. То что в Astro / Strapi нужно собирать руками.
3. **Self-hosted, без vendor lock**. Postgres + Node-процесс, всё под контролем. Никакая облачная CMS не сможет «закрыть аккаунт» или поднять цену.
4. **AI-friendly**. Схема — это код. Агент её читает, понимает, пишет/правит контент через REST или GraphQL. Расширение схемы — TS-миграция и `payload migrate`. Идеально для нашей агентной автоматизации.

### 6.3 Альтернативы и почему не они

| Решение | Хорошо в | Не подходит потому что |
|---|---|---|
| **Astro + MDX** | SSG-блог, скорость | Контент в git, нет редакторов, нет графа связей, нет админки |
| **Sanity** | Лучший UX редактора в индустрии | Облако, vendor-lock, оплата за документы и трафик |
| **Strapi** | Известность | Слабая типизация, медленные миграции через UI, экосистема слабее Payload |
| **Directus** | Гибкая «надстройка над Postgres» | Скорее data-админка, чем content-CMS |
| **WordPress** | Плагины на всё | PHP, плохо живёт с графом из 7 типов, Gutenberg чужд под наш поток |
| **Tilda / Webflow** | No-code лендинги | Один сайт = один интерфейс, нет CMS под граф |
| **Twenty в одиночку** | Минус один сервис | Twenty — CRM. Нет rich-text, нет media-library, нет версионности контента. Сэкономим систему — потеряем редакторский UX и потратим месяцы на ручную сборку этих фич поверх |

Полный разбор стека: [`docs/13-33-website/00-stack-rationale.md`](./00-stack-rationale.md).

## 7. Интеграция: Payload + Twenty + MemPalace + n8n

Это центральный вопрос архитектуры. Системы **не дублируют** друг друга — у каждой своя роль.

### 7.1 Разделение труда

```
TWENTY CRM                              PAYLOAD CMS
──────────                              ───────────
редакционный workflow:                  опубликованный контент:
  Idea → Draft → Publication              финальные статьи
карточка человека-автора                  продукты
сделки                                    эксперты (страницы)
история коммуникации                      темы / запросы / методы
комментарии и ревью                       события
аналитика воронки продаж                  медиа
                                          SEO-мета
                                          версии и черновики
```

Аналог в индустрии: **Trello + Contentful**, или **Notion + Sanity**. Каждая система делает то, в чём она лучше.

### 7.2 MemPalace — третий слой

MemPalace = архив *прочитанной литературы* + *опубликованного контента* для **семантического поиска**.

- Когда статья публикуется в Payload → n8n параллельно отправляет её в MemPalace, wing `13-33pubs`
- Книги, статьи, исследования (то что заливается в `Z:\inbox\books\` и `articles\`) — там же, отдельные wings
- Семантический поиск на сайте (V2) ищет одновременно в Payload (наши публикации) и в MemPalace (наша библиотека)

**Конкурентное преимущество:** поиск «про работу с тревогой» подтянет не только наши статьи, но и релевантные главы книг из библиотеки. Агент при написании новой статьи затягивает цитаты и факты прямо из MemPalace.

### 7.3 Полная схема инфры

```
                    Visitor
                       │
                  ┌────▼─────┐
                  │ Cloudflare CDN │
                  └────┬─────┘
                       │
              ┌────────▼────────┐
              │  Next.js (SSR/ISR) │  ← публичный фронт
              │  13-33.pro          │
              └────────┬────────┘
                       │ читает
              ┌────────▼────────┐
              │   Payload CMS    │  ← опубликованный контент
              │   (Postgres)     │     Articles, Products, Experts,
              └────────▲────────┘     Topics, Requests, Methods, Events
                       │ публикация
                ┌──────┴──────┐
                │  n8n flows   │  ← мост (workflow → publishing)
                └──────▲──────┘
                       │ webhooks при смене статуса
              ┌────────┴────────┐
              │   Twenty CRM    │  ← редакционный workflow
              │   (Postgres)    │     Idea → Draft → Publication
              └────────▲────────┘
                       │ создание карточек
        ┌──────────────┼──────────────┐
        │ Bot          │ Editors      │ Admin
        │ @claw1333    │ (web)        │ (web)
        └──────┬───────┘              │
               │                       │
        Whisper (локально) +
        LiteLLM → Sonnet/Opus
               │
        Авторы, эксперты (голос/текст)


  Параллельно:
  ┌─────────────────┐         ┌─────────────────┐
  │  MemPalace       │ ◄────── │  Uploader       │
  │  (Chroma /        │         │  (watches Z:\)  │
  │  pgvector V2)     │         └─────────────────┘
  └─────────┬─────────┘
            │ semantic search (V2)
            ▼
       Next.js Search API
```

### 7.4 Поток публикации (упрощённо)

```
1. Эксперт надиктовывает голосовое в @claw1333_bot
   ↓
2. Whisper транскрибирует + LiteLLM (Sonnet) черновикует
   ↓
3. Twenty: новая карточка статьи, статус "Idea"
   ↓
4. Автор/редактор правят в Twenty / в Payload-черновике
   → статус "Draft" → "Publication"
   ↓
5. n8n ловит изменение статуса → POST в Payload API
   ↓
6. Payload создаёт Article: тело (Lexical), теги (3 оси),
   автор, cover, SEO-мета. Возвращает payload_id и slug.
   ↓
7. Next.js ISR пересобирает /journal/<slug>/
   ↓
8. Cloudflare CDN кеширует → публично видно
   ↓
9. Twenty карточка получает обратно payload_id и url (двусторонняя связь)
   ↓
10. (V2) Payload-хук отправляет статью в MemPalace, wing 13-33pubs
    ↓
11. Plausible собирает события (клики, дочитывания, переходы на GetCourse)
    → дашборд внутри Payload-админки
```

### 7.5 Что **Twenty НЕ хранит**, а **Payload — да**

- Финальное тело статьи (rich text Lexical)
- Структурированные таксономии и связи между объектами
- Медиа (cover, иллюстрации, превью продуктов)
- SEO-мета (title, description, og:image)
- Версии и drafts опубликованного контента
- Schema-as-code, миграции, GraphQL-API под фронт

### 7.6 Что **Twenty хранит**, а **Payload — нет**

- Идеи в работе (до публикации)
- Внутренние комментарии/ревью
- Связи с людьми (кто писал, кто ревьюил, кто платит)
- Сделки, продажи, контакты клиентов
- Workflow-состояния с историей изменений

## 8. Контент-моделирование (Payload коллекции)

### 8.1 Сквозные таксономии

| Коллекция | Назначение |
|---|---|
| `topics` | Темы (предметные области) |
| `requests` | Запросы клиента |
| `methods` | Методы работы |
| `formats` | Форматы для журнала (эссе, разбор, интервью, дневник, манифест...) |

### 8.2 Контентные коллекции

| Коллекция | Ключевые поля | Связи |
|---|---|---|
| `articles` | title, slug, type (longread/blog), excerpt, body (lexical), cover, published_at, reading_time, featured | author→experts, topics[], requests[], methods[], related_products[] |
| `experts` | name, slug, role, bio, photo, contacts, calendar_link, telegram | methods[], products[] (как автор), articles[] (вычисляемая) |
| `products` | title, slug, type (course/event/session/group), short_desc, hero_image, price, getcourse_url, gallery[], schedule, format, featured | topics[], requests[], methods[], experts[], related_products[] |
| `events` | title, slug, date, time, location (Арбат/онлайн), capacity, price, getcourse_url, photos[], report_body | experts[], topics[], related_products[] |
| `quizzes` | title, slug, intro, questions[], result_logic, cta_offer | recommended_products[], recommended_articles[] (через теги) |
| `pages` | title, slug, body, layout_blocks[] | для статичных страниц |

### 8.3 Сервисные

- `users` — для ЛК (V2)
- `media` — изображения, файлы
- `redirects` — на случай переезда URL
- `nav` — кастомное меню (редактор может править)
- `site_settings` — глобальные тексты, телефоны, соцсети, дисклеймеры

## 10. brand-13-33 skill (параллельно)

Идея: один раз зафиксировать всё про бренд (палитра, типографика, лого, иконки, паттерны, тон-голоса) в виде Claude-skill, который любой агент в будущем сможет загрузить и применить — без ре-объяснения.

```
│   ├── logos/               — все SVG лого (8 lockup-вариантов + mark-only)
│   ├── icons/               — 17 SVG пиктограмм
│   ├── patterns/            — Моррис + мандала

├── templates/

│   ├── og-image.html

│   └── tg-post-formats.md
├── voice/
│   ├── examples-good.md
│   ├── examples-bad.md
│   └── tone-rules.md

```

### 10.2 Что нужно догрузить от тебя

1. **SVG/AI оригиналы лого** — 8 файлов (4 lockup × 2 цветовые версии) + mark-only × 2
2. **17 SVG пиктограмм** (сейчас есть только PDF)
3. **Декоративные паттерны** — Моррис + мандала как tile-able SVG
4. **Шрифтовые файлы** — `.otf` или `.ttf` всех весов DIN 2014 и Myriad Pro + лицензия (я сконвертирую в `.woff2` для веба)

Что я могу извлечь сам:
- Из SVG — точные пропорции, кривые, цвета (px-perfect)
- Из PDF — приблизительные пропорции (~5% погрешность) и точные цвета
- Из AI-файлов нативно не могу — нужен экспорт в SVG (`File → Export → Export As → SVG`)

### 10.3 Применение

После сборки skill, любой агент сможет:
- "Сделай OG-image для статьи X" — применит нужный lockup, цвета, шрифты
- "Напиши пост в Telegram от 13-33" — применит тон-голоса и форматы
- "Подготовь питч-слайды на 10 страниц" — использует slide-master + палитру + типографику
- "Сделай афишу для события на Арбате" — паттерны + лого + типографика

Это разовое вложение часов 5-10 работы, окупающееся **много раз** в будущем.
