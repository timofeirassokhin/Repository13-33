# Tenderland UI — патч-инструкции для пересборки сломанных автопоисков

**Дата:** 2026-05-06
**Цель:** починить 5 автопоисков, которые на активных тендерах дают 0 результатов, потому что используют поля модуля КОНТРАКТЫ вместо ТЕНДЕРОВ.

**Принцип починки:** заменить `contract_*` поля на `tender_*` поля. Образцы рабочих автопоисков — `Agilent (96702)`, `Фильтры мембранные (96701)`, `Оборудование (96700)`.

## 0. Расшифровка названий фильтров в UI Tenderland

| UI label (то что видишь в форме фильтра) | SystemName  | Что значит | Применять? |
|----|----|----|----|
| **«Название тендера»**     | `tender_name`         | Полнотекст по названию активного тендера | ✅ Да     |
| **«По извещению»**         | `tender_notification` | Текст официального извещения             | ✅ Да     |
| **«По документации»**      | `tender_files`        | Полнотекст всех файлов тендера           | ✅ Да     |
| **«Статус тендера»**       | `tender_status`       | Активные / завершённые / прочее          | ✅ Да (значение «Активные» = 1) |
| **«Начальная цена»**       | `tender_beginPrice`   | НМЦК активного тендера                   | ✅ Если нужен ценовой фильтр |
| «Поиск по продуктам»       | `contract_products`   | Поле уже подписанного контракта          | ❌ НЕТ — отсекает все активные тендеры |
| «Цена» (без уточнения)     | `contract_price`      | Цена подписанного контракта              | ❌ НЕТ — то же |
| «Дата подписания»          | `contract_signDate`   | Дата подписания контракта                | ❌ НЕТ — то же |
| «Категория»                | `tender_lotCategories`| Категории лота (tree_list)               | ⚠️ С осторожностью — слишком зажимает если выбрать узко |

> Главное правило: если фильтр в UI начинается со слова «Поиск по продуктам», «Цена контракта», «Дата подписания» или ссылается на контрактные сущности — **это не наш модуль**. Нам нужны только фильтры начинающиеся со слова «тендер» / «название тендера» / «по документации» / «по извещению» / «статус тендера».

## 2. Образец РАБОЧЕГО автопоиска — на что ориентироваться

### Agilent (96702) — простейший рабочий шаблон

```
AND:
  • «Название тендера» (tender_name)  — INCLUDE+EXCLUDE
  • «Статус тендера» = «Активные»     (value=1)
```

### Оборудование (96700) — продвинутый рабочий шаблон с OR-группой

```
AND:
  • OR:
    • «По документации» (tender_files)     — короткий узкий список маркеров (46 символов)
    • «Название тендера» (tender_name)     — широкий список (3015 символов)
  • «Статус тендера» = «Активные»            (value=1)
```

> **Эту структуру будем повторять в наших починенных автопоисках.** Узкий список в документации даёт прицельные совпадения по полнотексту, длинный список в названии — широкий охват.

## 3. Патч для каждого сломанного автопоиска

### 3.1. Все_приборы_аналитики_строгий (id 367074)

**Сейчас:**
```
AND:
  ❌ «Поиск по продуктам» (contract_products)  — INCLUDE 2045ч + EXCLUDE 1017ч
  ❌ «Категория» (tender_lotCategories)         — узкий список ID 451, 452, 490, ...
  ❌ «Цена» (contract_price)                    — от 5 000 000 ₽
  ❌ «Дата подписания» (contract_signDate)      — 2024-07-01..2025-12-31
```

**Что сделать:**
1. Открой автопоиск в UI Tenderland → нажми «Редактировать».
2. **Удали все 4 текущих фильтра** (нажми крестик/корзину рядом с каждым).
3. **Добавь** фильтр «По документации»:
   - В поле «Включить» — вставь строку из раздела **1.2** (короткие маркеры)
   - В поле «Исключить» — вставь строку из раздела **1.4** (EXCLUDE для приборов)
4. **Добавь** фильтр «Название тендера»:
   - В поле «Включить» — вставь строку из раздела **1.1** (полный список приборов)
   - В поле «Исключить» — то же значение из **1.4**
5. **Объедини оба текстовых фильтра в OR-группу** (в UI обычно есть кнопка «ИЛИ» или галка «искать в любом из полей»). Если такой кнопки нет — оставь оба как отдельные AND-фильтры (это будет жёстче, но всё равно сработает).
6. **Добавь** фильтр «Статус тендера» = «Активные» (значение 1).
7. Сохрани.

**Финальная структура должна выглядеть так:**
```
AND:
  • OR:
    • «По документации»  — INC ← раздел 1.2,  EXC ← раздел 1.4
    • «Название тендера» — INC ← раздел 1.1,  EXC ← раздел 1.4
  • «Статус тендера» = «Активные»
```

## 4. Быстрая шпаргалка — что в UI Tenderland НЕ нажимать

При создании/редактировании автопоиска в выпадающем меню «Добавить фильтр» Tenderland UI скорее всего покажет много полей. Чтобы не повторить ошибку:

| Если в UI написано...                | Это поле...                          | Можно? |
|---------------------------------------|---------------------------------------|--------|
| «Название тендера»                    | `tender_name`                         | ✅ |
| «По извещению»                        | `tender_notification`                 | ✅ |
| «По документации»                     | `tender_files`                        | ✅ |
| «Статус тендера»                      | `tender_status`                       | ✅ |
| «Начальная цена» / «НМЦК»             | `tender_beginPrice`                   | ✅ |
| «Регион»                              | `tender_region`                       | ✅ |
| «Дата публикации»                     | `tender_publishDate`                  | ✅ |
| «Дата окончания подачи»               | `tender_endDate`                      | ✅ |
| **«Поиск по продуктам»**              | `contract_products`                   | **❌** |
| **«Цена»** (без уточнения «начальная») | `contract_price`                     | **❌** |
| **«Дата подписания»**                 | `contract_signDate`                   | **❌** |
| **«Заказчик контракта»**              | `contract_customer`                   | **❌** |
| **«Поставщик»**                       | `contract_supplier`                   | **❌** |
| «Категория» (tree_list)               | `tender_lotCategories`                | ⚠️ Только если уверен в узком списке. По умолчанию НЕ ставить. |
| «Поиск по позициям планов»            | `plan_*`                              | ⚠️ Это модуль ПЛАНЫ. Для активных торгов не нужен. |

**Правило большого пальца:** если поле, цена или дата относится к слову **«контракт»** или **«подписание»** — **не используй**. Активные тендеры эти поля пустые имеют.

## 5. После применения патчей — проверка

По каждому починенному автопоиску:

1. Открой его в UI и сразу справа должно показаться **число найденных активных тендеров**. Если 0 — значит правка не применилась или фильтр всё ещё стоит на `contract_*`.
2. Сделай выгрузку в Excel для архивного периода (без даты-ограничения) и для актуальных (за неделю).
3. Пришли xlsx — я прогоню через анализатор и скажу:
   - Объём (ожидается: 100-600 за 1.5 года для приборов; 50-200 за 1.5 года для расходников)
   - Релевантность (ожидается: 70-90%)
   - Не пробрался ли мусор (дорожники, МАФ, стоматология)
   - Профиль клиентов (должны быть НМИЦ, НИЦ, ВУЗы, ФБУЗ — не муниципалитеты)

Если результат сильно не такой — значит в UI что-то ещё стоит из старого. Пришлю обновлённый дамп через API и доисправлю инструкцию.

## 6. Что после активации Search/Find (завтра)

После активации модуля API Поиск всё это становится временным — мы переносим конфигурацию фильтров в код проекта `gluvex_tender_machine` как JSON-файлы под `config/searches/`. Автопоиски в UI остаются как резервный канал, но рабочая воронка идёт через `/Search/Find` напрямую.
