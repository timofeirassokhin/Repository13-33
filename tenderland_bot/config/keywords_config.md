# Tenderland — автопоиски по аналитическому оборудованию

**Дата подготовки:** 2026-05-05
**Версия:** 1.0 (финальная сборка)
**Источники:**
- `Tenderland_keywords_config.xlsx` — базовая структура, российская специфика, операционные правила
- `tenderland_analytical_instruments_keywords.md` — расширенное покрытие моделей и две новые категории (УФ-Вид, ФТИР)

**Цель:** настроить набор автопоисков в кабинете Tenderland, покрывающих весь портфель Глювекса по инструментальной аналитике, с минимальным шумом и без потери релевантных тендеров.

## 2. Алгоритм настройки в Tenderland UI

Один и тот же набор шагов **повторить 8 раз** (по числу автопоисков).

| Шаг | Действие                                                                                        |
|-----|--------------------------------------------------------------------------------------------------|
| 1   | Создать новый автопоиск с именем из таблицы 1 (например `01_LC_LCMS_GPC_Prep`).                  |
| 2   | Добавить **один** фильтр «Поиск по ключевым словам». В поле «Включать» — INCLUDE-строка из раздела 4 для соответствующего автопоиска. В поле «Исключать» — общая EXCLUDE-строка из раздела 5. |
| 3   | Добавить фильтр «Дата публикации» (range): **от = СЕГОДНЯ−7 дней**, до = пусто.                  |
| 4   | Добавить фильтр «Дата окончания подачи» (range): **от = СЕГОДНЯ**, до = пусто. Это отсекает уже закрытые тендеры на стороне Tenderland. |
| 5   | Сохранить → скопировать `id` из URL (`?id=XXXXX`).                                               |
| 6   | Прислать список из 8 пар «имя → id» в `tenderland_bot/config/autosearches.toml` (или просто в чат). |

**Важно про даты:** Tenderland хранит **абсолютные** даты, не «скользящее окно». Поэтому даты `от` в шагах 3-4 нужно вручную обновлять примерно раз в неделю. Альтернатива — убрать оба фильтра дат и фильтровать в CLI после получения; это будет реализовано опцией `--active-only` в команде `export`, но цена — ~15-30 единиц лимита в день на «выгрузку и сразу выкидывание» истёкших тендеров.

## 4. Синтаксис ключевых слов Tenderland (краткая шпаргалка)

| Оператор   | Значение                                                    | Пример                              |
|------------|--------------------------------------------------------------|-------------------------------------|
| `(пробел)` | OR между терминами                                          | `ВЭЖХ HPLC` → один из двух           |
| `++`       | AND со стеммингом — оба слова в любых формах                | `жидкостн++хроматограф` → «жидкостной хроматограф», «жидкостная хроматография» и т.д. |
| `+`        | соединение в фразу при точном совпадении                    | `тройн+квадрупол`                    |
| `=`        | префикс точного совпадения, отключает русскую морфологию    | `=HPLC`, `=Q-TOF`, `=ICP-MS`         |

Латиница автоматически воспринимается как точное совпадение, поэтому для `HPLC` префикс `=` не обязателен — оставляем для читаемости и устойчивости к будущим изменениям парсера.

## 8. Чеклист после первого прогона (сделать через 1 неделю работы)

| № | Что проверить                                                                                               | Действие при найденной проблеме                                          |
|---|--------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------|
| 1 | Не отсекает ли EXCLUDE релевантные лоты с упоминаниями `пробир`, `посуд`, `гель`, `набор+лаборатор+диагност` | Снять конкретный термин из EXCLUDE, перенастроить                         |
| 2 | Сколько единиц лимита Tenderland уходит на скачивание архивов (`tender_files`)                              | Если близко к 300/день — отключить скачивание для тендеров с НМЦК < N руб. через CLI-фильтр; либо включить дедуп БД (планируется к Этапу 3) |
| 3 | Покрытие на дооснащении — ловятся ли тендеры с формулировками «модернизация», «дооснащение», «поставка дополнительного оборудования к ВЭЖХ» | Добавить в INCLUDE соответствующего автопоиска: `модернизац дооснащен дополнительн++оборудован` |
| 4 | Дублирование тендеров между автопоисками (один лот в `01_LC_LCMS` и `05_ICP_MS` если он на «комплексное оснащение лаборатории») | Это нормально. CLI дедуплицирует на уровне общего отчёта по `tender_id`   |
| 5 | Есть ли «слепые зоны» по российским производителям, не попавшим ни в один список                            | Добавить в соответствующий INCLUDE: «Хромос», «Хроматэк», «Метрохм», «КВАНТ», «МГА», «Цвет», «Маэстро» (часть уже добавлена) |
| 6 | Качество фильтра по дате `endDate ≥ today` — не ловятся ли уже закрытые тендеры (если запрашивающий не обновил дату вручную) | Перейти на клиентский фильтр через `--active-only` в CLI                  |

## 9. Связь с CLI `tenderland_bot`

После того как все 8 автопоисков созданы и есть их `id`:

1. Заполнить `tenderland_bot/config/autosearches.toml`:
   ```toml
   [[autosearch]]
   id = 96704
   topic = "01_LC_LCMS_GPC_Prep"

   [[autosearch]]
   id = ...
   topic = "02_GC_GCMS"
   # ... и так все 8
   ```
2. Команда `python -m tenderland_bot export-all` пройдётся по всем автопоискам по очереди и разложит результаты по структуре:
   ```
   Z:\tenders\01_LC_LCMS_GPC_Prep\<DDMMYY>.{xlsx,md}
   Z:\tenders\01_LC_LCMS_GPC_Prep\DDMMYY\*.zip
   Z:\tenders\02_GC_GCMS\...
   ```
3. Дедупликация по `tender_id` через локальную SQLite-таблицу `processed_tenders` (вводится в Этапе 3 разработки) — не качаем zip-архивы для уже виденных тендеров, экономим лимит.
