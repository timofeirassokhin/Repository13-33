# Контракт: что fetcher отдаёт анализатору ТЗ

Этот документ — стартовая точка для **отдельной ветки/чата** по агенту-анализатору
техзаданий. Там не нужно знать ничего про Tenderland API — анализатор работает
**только с локальными файлами**, которые fetcher (`tenderland_bot`) сложил на диск.

---

## 1. Что fetcher делает (двумя строками)

CLI `python -m tenderland_bot export <автопоиск>`:
1. Тянет список тендеров из выбранного автопоиска через Tenderland API.
2. Для каждого тендера качает zip-архив всей документации.
3. Пишет два сводных файла (Excel + Markdown) и раскладывает архивы по дате.

Анализатор **не дёргает API** и **не знает API-ключ**. Он смотрит только на файлы.

---

## 2. Структура каталога `Z:\tenders\`

```
Z:\tenders\
└── <Autosearch>\                          # одна папка на автопоиск
    ├── <Autosearch>_DDMMYY.xlsx           # сводный список за день, Excel
    ├── <Autosearch>_DDMMYY.md             # тот же список, Markdown
    ├── <Autosearch>_DDMMYY.xlsx           # история накапливается рядом
    ├── <Autosearch>_DDMMYY.md
    └── DDMMYY\                             # подпапка дня = zip-архивы
        ├── <regnumber>__<slug-name>__<TL-id>.zip
        ├── <regnumber>__<slug-name>__<TL-id>.zip
        └── ...
```

Пример:
```
Z:\tenders\Memmert\Memmert_050526.xlsx
Z:\tenders\Memmert\050526\0387200004226000005__postavka-termostata__TL2530033598.zip
```

- `<Autosearch>` — slug имени автопоиска (транслит, без пробелов).
- `DDMMYY` — день выгрузки.
- `<TL-id>` (`TL2530033598`) — **глобально уникальный ID тендера** в Tenderland.
  Используй его как primary key, если нужно дедуплицировать тендеры между
  автопоисками или между датами.

---

## 3. Структура строки в Excel/Markdown

Колонки в Excel (одна строка = один тендер/лот):

| Колонка               | Поле в коде      | Тип    | Пример |
|-----------------------|------------------|--------|--------|
| Реестровый номер      | `reg_number`     | str    | `0332300328026000039` |
| Название              | `name`           | str    | `Поставка термостата...` |
| Начальная цена        | `begin_price`    | float ₽| `218809.33` (0.0 если не указана у источника) |
| Заказчик              | `customer`       | str    | `БУ "ВЕТЕРИНАРНАЯ ЛАБОРАТОРИЯ"` |
| Дата публикации       | `publish_date`   | str ISO| `2026-05-05 16:25` |
| Дата окончания подачи | `end_date`       | str ISO| `2026-05-13 10:00` |
| Регион                | `region`         | str    | `Ханты-Мансийский АО` |
| Тип закупки           | `type_name`      | str    | `ФЗ 44: Запрос котировок` |
| Категории лота        | `categories`     | str    | `Медицинские товары разные` |
| Источник (ЭТП)        | `etp_link`       | str    | `http://www.rts-tender.ru` |
| Документы (zip URL)   | `files_url`      | str    | прямая ссылка на API (содержит API-ключ — **игнорируй**) |
| Entity ID             | `entity_id`      | str    | `TL2530033598` |
| Локальный архив       | `local_zip`      | str    | абсолютный путь к zip-у |

**Анализатор должен брать `local_zip`** и работать с ним. Если поле пустое — архив
не скачался (нет документации, ошибка, или fetcher запускался с `--no-files`).

Markdown-файл содержит ту же информацию в человекочитаемом виде. Excel — рабочая
лошадка для batch-обработки (`openpyxl.load_workbook`).

## 4. Что обычно лежит внутри zip-архива

По наблюдениям на ФЗ-44 (Memmert тест):

```
архив.zip
├── Печатная форма извещения NNNNN.html              # формальное извещение
├── Расчет и обоснование НМЦК.pdf                    # начальная цена + обоснование
├── NN-MM-YYYY ЭА Общие условия закупки (раздел I извещения).doc
├── NN-MM-YYYY ЭА Описание объекта закупки (раздел II извещения).doc   # ← ТЕХЗАДАНИЕ
└── NN-MM-YYYY ЭА_Проект контракта.docx              # проект контракта
```

**Главный файл для анализатора — "Описание объекта закупки"** (раздел II): там
характеристики прибора в формате таблицы или текста.

На коммерческих площадках формат произвольный. Возможные расширения:
`.pdf`, `.doc`, `.docx`, `.xls`, `.xlsx`, `.html`, `.rtf`, `.txt`, `.zip`
(вложенный архив!), `.rar`, `.7z`.

**Нет гарантии**, что характеристики структурированы. Бывает:
- Таблица в DOCX/XLSX (характеристика → значение).
- Текстом в PDF (часто скан, нужен OCR).
- В нескольких файлах разом (общее ТЗ + спецификация).
- В виде скана PDF без OCR-слоя (придётся прогонять через `tesseract` / Vision).

## 5. Что нужно построить в анализаторе (на верхнем уровне)

1. **Распаковщик zip** → каталог `unpacked/<TL-id>/` с файлами.
2. **Классификатор файлов**: какой из них ТЗ, какой контракт, какой расчёт цены.
   Эвристика по имени файла + содержимому.
3. **Экстрактор характеристик** из ТЗ:
   - DOCX/XLSX → структурный разбор таблиц.
   - PDF с текстовым слоем → `pdfplumber`.
   - PDF-скан → OCR.
   - Финальный нормализатор → JSON-список `{характеристика, значение, единица, обязательность}`.
4. **Каталог наших приборов** — отдельная задача (см. раздел 7), без него матчинг
   невозможен.
5. **Матчер**: характеристики тендера vs характеристики каждого нашего прибора.
   На выходе — score + объяснение + флаги «не проходим по параметру X».
6. **Запись результата** обратно в ту же папку дня:
   ```
   Z:\tenders\050526\Memmert\analysis\<TL-id>.json
   Z:\tenders\050526\Memmert\analysis\<TL-id>.md       # человекочитаемое резюме
   ```

---

## 6. Что НЕ должен делать анализатор

- ❌ Не дёргать Tenderland API. Если файл не скачан — это баг fetcher'а, а не повод
  идти за ним напрямую.
- ❌ Не лезть в `.env` fetcher'а — у анализатора может быть свой `.env` с
  LLM-ключами (`ANTHROPIC_API_KEY`, OCR-сервис и т.д.).
- ❌ Не модифицировать сводные Excel/MD fetcher'а. Свои результаты — в
  `analysis/<TL-id>.{json,md}` рядом с архивами.
- ❌ Не удалять и не перемещать zip-архивы. Распаковывать в отдельный `unpacked/`.

## 7. Открытая задача-предусловие: каталог приборов

Без структурированного каталога приборов матчер невозможен. Это **третья
независимая ветка**. Минимальный shape:

```json
{
  "instrument_id": "memmert-un55",
  "brand": "Memmert",
  "model": "UN 55",
  "category": "сушильный шкаф",
  "specs": [
    {"name": "температурный диапазон", "value_min": 30, "value_max": 300, "unit": "°C"},
    {"name": "объём камеры", "value": 53, "unit": "л"},
    {"name": "точность поддержания температуры", "value": 0.5, "unit": "°C"}
  ],
  "consumables_for": [],
  "datasheets": ["s3://catalogue/memmert/un55-datasheet.pdf"]
}
```

Источники: PDF-каталоги производителей, наш ассортимент в 1С/Excel, сайт
производителя. Это работа на отдельный спринт, скорее всего полу-ручная +
LLM-извлечение.
